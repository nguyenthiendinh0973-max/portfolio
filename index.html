SQL Server / MySQL: Giả Lập Tối Ưu Hóa Truy Vấn & Đánh Chỉ Mục (+25%)

So sánh trực quan thời gian thực thi giữa truy vấn Table Scan thông thường và Indexed Stored Procedure.

Query Plan & Clustered Index +25% - 70% Execution Speedup
Truy vấn thông thường (Table Scan) Chưa chạy 
SELECT o.*, c.name, p.sku 
FROM Orders o
JOIN Customers c ON o.customer_id = c.id
JOIN OrderDetails d ON o.id = d.order_id
WHERE o.created_at >= '2024-01-01'
ORDER BY o.total_amount DESC;

• Trạng thái: Full Index Scan không dùng Clustered Index.

• Bộ nhớ I/O: 1,420 Reads trên 100,000 dòng dữ liệu.

Truy vấn Tối Ưu (Stored Proc + Composite Index) Chưa chạy 
-- Sử dụng Stored Procedure & Covering Index
EXEC sp_GetOptimizedOrdersSummary
  @StartDate = '2024-01-01',
  @TopN = 50;
-- INDEX: IX_Orders_Covering (created_at, total_amount)

• Trạng thái: Index Seek chính xác, giảm 75% Logical Reads.

• Hiệu suất thực tế theo CV: Tăng 25% - 65% tốc độ xử lý.

Thử nghiệm Benchmark trên tập dữ liệu mô phỏng 100,000 records:

Bấm nút bên cạnh để đo độ trễ truy vấn (Execution Latency) trực tiếp.

Biểu đồ so sánh thời gian thực thi: Nhanh hơn 28.5%
Chưa tối ưu (Table Scan): 380 ms
Sau khi tối ưu (Stored Proc & Index): 285 ms

Kịch bản Apps Script (Trích đoạn code thực tế): 
function syncSheetToDatabase() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Production_Logs");
  const data = sheet.getDataRange().getValues();
  const headers = data[0];
  
  const payload = data.slice(1).map(row => ({
    lot_number: row[0],
    item_name: row[1],
    quantity: row[2],
    timestamp: new Date().toISOString()
  }));

  const res = UrlFetchApp.fetch("https://api.erp.internal/sync", {
    method: "post",
    contentType: "application/json",
    payload: JSON.stringify(payload)
  });
  
  Logger.log("Đã đồng bộ thành công: " + payload.length + " dòng dữ liệu.");
}
